【二、新功能：标签筛选池系统】★ 重要功能

功能概述：
从缓存中筛选特定标签，创建自定义标签池用于生成。
例如：只选择包含 "1girl" 的标签，排除 "2girls" 的标签。

【2.1 后端功能扩展】

文件：cache_db.py

新增方法：

1. filter_tags_by_keywords(must_include, must_exclude)
   - 功能：按关键词筛选标签
   - 参数：
     * must_include: 必须包含的关键词（逗号分隔）
     * must_exclude: 必须排除的关键词（逗号分隔）
   - 返回：匹配的 (id, tags) 列表

2. create_filtered_pool(filtered_ids)
   - 功能：从选中的 ID 创建筛选池
   - 参数：filtered_ids - 标签 ID 列表
   - 返回：筛选池中的标签数量
   - 说明：创建独立的 filtered_pool 表存储筛选结果

3. get_filtered_pool_status()
   - 功能：获取筛选池状态
   - 返回：状态字符串（如 "筛选池: 50 条"）

4. use_filtered_pool(use_pool)
   - 功能：切换使用筛选池或主缓存
   - 参数：use_pool - True 使用筛选池，False 使用主缓存
   - 说明：设置保存到数据库，重启后保持

5. is_using_filtered_pool()
   - 功能：检查当前是否使用筛选池
   - 返回：布尔值

6. get_next_tags_from_pool(loop)
   - 功能：自动从筛选池或主缓存获取下一条标签
   - 参数：loop - 是否循环
   - 说明：根据设置自动选择数据源

【2.3 使用流程】

步骤 1：批量爬取标签到缓存
- 设置搜索条件，点击 "🚀 开始批量爬取"
- 例如：爬取 20 页，获得 2000 条标签

步骤 2：筛选标签
- 在 "必须包含" 输入：1girl
- 在 "必须排除" 输入：2girls,multiple_girls
- 点击 "🔍 筛选标签"
- 查看筛选结果表格

步骤 3：创建筛选池
- 从筛选结果中复制需要的 ID
- 粘贴到 "选中的 ID" 输入框（例如：1,5,10,23,45）
- 点击 "✅ 创建筛选池"
- 确认筛选池状态显示正确数量

步骤 4：切换到筛选池
- 勾选 "使用筛选池（而非主缓存）"
- 点击 "🔄 切换" 按钮
- 确认状态显示 "[当前使用筛选池]"

步骤 5：生成图片
- 勾选 "生成时使用此缓存"
- 设置 Batch count 和 Batch size
- 点击 Generate
- 每张图会从筛选池按顺序获取标签

【三、技术细节】

【3.1 数据库结构】

主缓存表（tags）：
- id: 自增主键
- tags: 标签字符串

筛选池表（filtered_pool）：
- id: 自增主键
- tags: 标签字符串（从主缓存复制）

元数据表（metadata）：
- key: 键名
- value: 值
- 新增键：use_filtered_pool (0/1)

【3.2 工作原理】

1. 筛选过程：
   - 使用 SQL LIKE 查询匹配关键词
   - 支持多个关键词的 AND 逻辑
   - 必须包含：所有关键词都要匹配
   - 必须排除：所有关键词都不能匹配

2. 筛选池创建：
   - 创建独立的 filtered_pool 表
   - 从主缓存复制选中的标签
   - 不影响主缓存数据

3. 数据源切换：
   - 通过 metadata 表记录当前使用的数据源
   - get_next_tags_from_pool() 自动判断使用哪个表
   - 索引独立管理，切换后从 0 开始

4. 生成时使用：
   - before_process() 调用 get_next_tags_from_pool()
   - 自动根据设置选择数据源
   - 支持循环模式

【3.3 性能优化】

- 使用 SQL 索引加速查询
- 筛选池独立存储，避免重复筛选
- 索引保存到硬盘，重启后继续

【四、注意事项】

1. 筛选池是独立的
   - 创建筛选池不会修改主缓存
   - 可以随时切换回主缓存
   - 删除主缓存不会删除筛选池

2. 索引管理
   - 主缓存和筛选池共用一个索引
   - 切换数据源后索引会重置为 0
   - 点击 "重置索引" 会重置当前使用的数据源

3. 关键词匹配
   - 使用模糊匹配（LIKE %keyword%）
   - 区分大小写（取决于数据库设置）
   - 支持下划线和空格（1girl 和 1_girl 不同）

4. ID 选择
   - 可以手动输入 ID（逗号分隔）
   - 也可以从筛选结果表格复制 ID
   - 无效的 ID 会被自动忽略

5. 数据持久化
   - 筛选池保存在数据库中
   - 重启 WebUI 后仍然存在
   - 使用筛选池的设置也会保存

【五、常见问题】

Q1: 筛选池和主缓存有什么区别？
A1: 主缓存包含所有爬取的标签，筛选池只包含你选择的标签。
    筛选池用于精确控制生成内容。

Q2: 可以创建多个筛选池吗？
A2: 当前版本只支持一个筛选池。创建新的会覆盖旧的。

Q3: 筛选池会占用多少空间？
A3: 取决于选择的标签数量。每条标签约 100-500 字节。

Q4: 如何清空筛选池？
A4: 创建一个空的筛选池（不输入任何 ID），或切换回主缓存。

Q5: 筛选池可以追加吗？
A5: 当前版本不支持追加，只能覆盖。如需追加，请手动合并 ID。

Q6: 关键词筛选支持正则表达式吗？
A6: 不支持。只支持简单的模糊匹配。

Q7: 如何备份筛选池？
A7: 复制 user/cache/tag_cache.db 文件即可。

Q8: 筛选池的索引如何管理？
A8: 与主缓存共用索引。切换数据源后会自动重置。
